# S8·S9 데이터 고르기

후보 찾기는 AI가, 되는지 판정은 `scripts/check_source.py`가, 고르기는 사람이 한다. 모든 조회는 메타데이터만 읽는다(`bq ls`·`bq show`, `INFORMATION_SCHEMA`, `__TABLES__`). 데이터 값은 읽지 않는다.

## 1. 주제로 후보 찾기 (S8)

1. 사용자의 주제(한글 가능)를 영어 검색어 2~4개로 바꾸고, 그 단어를 먼저 보여 준다. 예: "날씨" → `weather`, `noaa`, `climate`.
2. 공개 데이터셋 목록을 한 번 받는다. 목록 조회는 쿼리가 아니라 스캔 비용이 없다.

```
bq ls --project_id=bigquery-public-data --max_results=1000 --format=json
```

3. 데이터셋 이름을 밑줄(`_`)로 나눈 단어 중 검색어와 같거나 검색어로 시작하는 것을 모두 고른다.
   "날짜 관련"처럼 주제의 말이 모호하면 날짜 칸(컬럼)이 있는 데이터로 해석한다(날짜 파티션이 아님). 해석을 한 줄로 되짚는다.
4. 맞는 데이터셋을 쉼표로 이어 한 번에 거른다. "후보를 찾는 데 1~2분 걸립니다"라고 먼저 말한다. 40개를 넘으면 이름 목록만 보여 주고 검색어를 좁히자고 한다.

```
python .claude/skills/data-harness/scripts/check_source.py --datasets 이름1,이름2,이름3 --filter
```

   - 스크립트가 `ai_dev`와 같은 리전이고 판정 "가능" 테이블(500 MB 이하, snapshot)이 1개 이상인 데이터셋만 설명 원문과 함께 낸다(형식 문구는 건너뜀). 데이터셋마다 다시 조회하지 않는다.
   - 뺀 개수 줄("리전이 달라서 뺀 것 N개" 등)을 그대로 옮긴다.
   - 종료 1(남은 것 없음) → 다른 단어로 다시. 종료 2(조회 실패) → 3절의 조회 실패 행.
5. 후보 표를 **알파벳순**으로 보여 준다. 칸: 데이터셋 이름, 한글 한 줄 설명, 영어 원문 첫 문장, 리전. 한글 설명은 스킬이 원문을 번역해 처음부터 넣는다(원문이 비었으면 "설명 없음"). 순위·"추천"·"쉬운"·"좋은"을 쓰지 않는다.
6. 고르게 한다(권장 표시 없음).
   - 후보가 4개 이하: 후보를 알파벳순 선택지로(AskUserQuestion). 설명은 "리전 · 설명 첫 문장(한글)". 후보가 1개면 두 번째 선택지는 "검색어 바꾸기".
   - 후보가 5개 이상: 본문 표를 보이고 "고른 이름을 채팅에 적어 주세요. 검색어를 바꾸거나 콘솔에서 직접 찾고 싶으면 그렇게 적어 주세요"라고 한다.
   - 입력한 이름이 후보에 없으면 그대로 S9 판정을 돌린다(후보 밖 데이터도 고를 수 있다).
7. 사용자가 "아무거나 골라 줘"라고 하면 고르지 않는다. 판정을 돌린 적이 있으면 "가능"인 후보만 남긴 표를 다시 보이고 하나를 고르게 한다.

목록 조회가 권한으로 막히거나 결과에 리전이 없으면, START.md 부록 A-1의 콘솔 마켓플레이스 절차로 사용자가 고르게 하고 그 이름을 받는다.

## 2. 되는지 판정 (S9)

```
python .claude/skills/data-harness/scripts/check_source.py --dataset 데이터셋이름
```

스크립트가 내는 표를 **그대로** 옮긴다(예외는 아래 "이름만 다른 표 묶기" 하나). 판정을 AI가 바꾸거나 "이게 더 낫다"고 말하지 않는다. 맨 위에 데이터셋 판정 한 줄(위치·리전), 테이블은 가능 → 조건부 → 불가 순서다.

| 항목 | 가능 | 조건부 | 불가 |
|---|---|---|---|
| 위치 | `bigquery-public-data` 안 | | 다른 프로젝트 |
| 리전 | `ai_dev`와 같음 | | 다름 |
| 종류 | 테이블 | 뷰: 쓸 컬럼 dry-run이 500 MB 이하면 snapshot만 | 외부 테이블, 테이블·뷰가 아닌 것(ML 모델 등) |
| 크기 | 500 MB 이하 → snapshot | | 500 MB 초과(날짜 파티션이 있어도 "이 안내의 범위 밖") |
| 이름 모양 | 보통 이름 | | `이름_YYYYMMDD` 날짜 분할 |

개인정보 후보(컬럼 이름에 `name`·`email`·`address` 같은 단어가 든 것)는 판정을 바꾸지 않는다. "개인정보 후보" 칸에 컬럼 이름만 보이고, 실제로 개인정보인지는 S11에서 사람이 정한다.

종료 코드: 0 가능·조건부 테이블이 1개 이상, 1 모두 불가, 2 조회 실패(권한·네트워크).

**이름만 다른 표 묶기**: 이름이 연도·숫자만 다른 표가 많으면 한 줄로 묶어 보인다. 예: "gsod1929 ~ gsod2024 (76개, 연도마다 한 표)". 처음·끝 이름과 개수는 스크립트 출력에서 센 것만 쓴다. 판정이 같은 표끼리만 묶고, 판정이 다른 표는 따로 보인다. 크기는 가장 작은 것 ~ 가장 큰 것으로 쓴다. 묶은 줄 아래에 "고르면 그중 하나(한 해)를 씁니다. 여러 해를 합치지 않습니다"라고 알려 준다(연도가 아니면 "그중 하나"). 선택지에는 묶은 줄을 넣지 않고, 쓸 표 이름 하나를 채팅에 적게 한다.

표 아래에 "쓸 수 있는 테이블"(판정이 가능·조건부이고 적재 방식이 snapshot) 설명 표를 덧붙인다: 테이블, 한글 한 줄 설명(판정표의 설명 원문을 번역), 날짜 칸. 무슨 테이블인지 더 알아야 하면(설명이 비었거나 사용자가 칸을 물으면) 아래로 설명과 칸 목록을 본다. 값의 뜻과 주의점(예: 기간 중 관측 대상 수가 바뀜)을 설명에서 알 수 있으면 함께 말한다.

```
python .claude/skills/data-harness/scripts/check_source.py --dataset 데이터셋이름 --table 테이블이름
```

이 안내는 snapshot(테이블 전체를 읽음) 하나만 쓴다. 500 MB를 넘는 표와 그 안의 중첩 칸은 "이 안내의 범위 밖"이라고 말하고 선택지에 넣지 않는다. 손으로 하는 길(START 부록 A)에서 날짜별 추가 적재를 쓰려면 `--allow-large`를 붙여 판정한다.

쓸 테이블 고르기(AskUserQuestion, 여러 개 선택, 권장 표시 없음): "쓸 수 있는 테이블"만 선택지로. 4개를 넘으면 표를 보이고 채팅에 적게 한다. "불가" 테이블은 선택지에 넣지 않는다. 뷰를 고르면 인터뷰(S13)에서 쓸 컬럼을 정한 뒤 dry-run으로 다시 판정한다.

## 3. 범위 밖일 때 보여 줄 말과 선택지

| 경우 | 보여 줄 말 | 선택지 |
|---|---|---|
| 리전 다름 | 이 데이터는 {리전}에 있고 당신의 `ai_dev`는 {리전}에 있습니다. 이 키트는 리전이 다른 데이터를 쓸 수 없습니다. | 같은 주제로 같은 리전 후보만 다시 보기 / 다른 주제 |
| 모든 테이블이 500 MB 초과 | 테이블이 커서 한 번에 읽으면 비용 상한(500 MB)을 넘습니다. 이 안내의 범위 밖입니다. | 같은 데이터셋의 다른 테이블 / 다른 후보 |
| 날짜 분할 테이블 | 이 데이터는 날짜마다 테이블을 따로 만들어 두었습니다. 이 키트는 여러 테이블을 한 번에 읽지 않습니다. | 다른 테이블 / 다른 후보 |
| 외부 테이블 | 이 테이블은 BigQuery 밖에 있는 파일을 가리킵니다. 읽는 양을 미리 알 수 없어 쓰지 않습니다. | 다른 테이블 / 다른 후보 |
| 여러 데이터셋을 섞고 싶음 | 승인, 개인정보 검토, 원본과 맞는지 검사가 모두 데이터 하나를 기준으로 짜여 있습니다. 같은 데이터 안의 표끼리는 합칠 수 있습니다. | 하나를 고르기 |
| 조회 실패(종료 2) | 데이터 정보를 읽지 못했습니다. 데이터 문제가 아니라 연결이나 권한 문제입니다. | S4 신원 확인 다시 / 담당자 문의 |
