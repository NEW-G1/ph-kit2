# 막혔을 때 (화면 문구 → 할 말 → 다음 단계)

사용자용 기준은 `docs/kit/START.md` "자주 막히는 곳" 하나다. 이 파일은 같은 내용을 스킬이 쓰기 좋게 단계별로 옮긴 것이라, START.md를 먼저 고치고 여기를 맞춘다. 둘이 다르면 START.md를 따른다. 표에 없는 문구는 그대로 보여 주고 "키트를 준 담당자에게 이 문구와 단계 번호를 알려 주세요"라고 한다.

반려 내용 마지막 3건 보기(`-Encoding UTF8`이 없으면 한글이 깨짐):

```
Get-Content .dev\rejections.jsonl -Encoding UTF8 -Tail 3
```

| "dry-run ... bytes > 상한" | 그 테이블은 한 번에 읽는 양이 상한을 넘습니다 | 다른 테이블이나 데이터. 원천이 바뀌면 S8부터 |
| "ai_dev 기본 파티션 만료(N일)보다 오래된 ds" | 고른 날짜가 `ai_dev`에 걸린 기본 파티션 만료보다 오래됐습니다. 키트의 `ai_dev`는 만료 없음이 기준이라 설정이 다른 것이고, 설정은 담당자 권한입니다 | 메시지를 담당자에게 |
| `contract_change`로 멈춤 | AI가 "요구서를 바꿔야 고칠 수 있다"고 판단했습니다. 멈춘 `build` 브랜치는 올리거나 머지하지 않습니다 | `Get-Content .dev\progress.md -Encoding UTF8 -Tail 40`의 이유를 담당자에게. 정해진 수정 문장으로 "요구서를 고친 뒤 다시 시작하기" |

| 같은 L2 `runtime_error`, 마지막 반려에 "Column ... is not present in table ...ai_dev.(테이블)" | 예전에 만든 같은 이름 테이블이 `ai_dev`에 남아 있습니다. AI는 테이블을 지울 수 없습니다 | 담당자에게 `ai_dev` 비우기 요청. 비워지면 같은 명령. 멈춤이 `same_type_3x`면 다시 시작 명령도 담당자에게 |
| `input_invalid`로 멈춤 | 입력(설정·요구서·기록) 문제로 멈췄습니다 | 이유를 적어 담당자에게 |
| "rule 문장에 쓸 수 없는 글자" | 요구서 검사 문장에 작은따옴표 같은 글자가 있습니다 | "요구서를 고친 뒤 다시 시작하기". 2번 문장: "contract.json의 checks rule 문장에서 작은따옴표, 중괄호, 역슬래시를 빼 줘. 뜻은 바꾸지 마" |
| "요구서 절 번호 1~9여야 함" | 요구서 절 번호가 형식에 맞지 않습니다 | "요구서를 고친 뒤 다시 시작하기". 2번 문장: "contract.json에서 requirements의 section 값을 그 요구의 근거가 된 요구서 절 번호(1~9, 따옴표 없는 숫자)로 고쳐 줘. 다른 곳은 고치지 마" |
| "iteration 0 커밋 이후 입력 파일이 바뀜" 또는 "새 작업 브랜치" | 요구서를 다시 머지한 뒤 예전 `build` 브랜치에서 돌렸습니다 | "요구서를 고친 뒤 다시 시작하기" 4번만(새 이름 `build2`) |
| Claude 사용량 한도·네트워크로 멈춤 | 한도가 풀린 뒤 같은 명령을 다시 실행하면 이어집니다 | 같은 명령(incremental이면 같은 `--ds`) |
| `HARNESS_ROLE`이 남았다는 거절 | 이 창에 루프 안쪽 표시가 남아 있습니다 | 루프 메시지의 `Remove-Item Env:HARNESS_ROLE` 뒤 다시 |
